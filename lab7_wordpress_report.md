# Лабораторная работа №7 «CMS WordPress» (7-1 и 7-2)

**Тема:** установка и настройка CMS WordPress на локальный сервер, наполнение сайта.

**Реализация:** каталог [lab7_wordpress/](lab7_wordpress/). Вместо Open Server Panel / Denwer локальный веб-сервер собран в Docker из тех же компонентов, что в методичке:

| Методичка (Open Server / Denwer) | Здесь (Docker) |
|---|---|
| Apache + PHP | `wordpress:php8.3-apache` (WordPress 7.1.3) |
| MySQL | `mysql:8.4`, база `wptest`, кодировка utf8mb4 |
| phpMyAdmin | `phpmyadmin:5` |
| папка `domains\wptest.ru` | том `wpdata` |
| установка из браузера, ручная работа в Консоли | WP-CLI: [setup/seed.sh](lab7_wordpress/setup/seed.sh) делает все шаги 7-1 и 7-2 |

Плюс в том, что весь сайт собирается одной командой одинаково и на ноутбуке, и на сервере. В Консоли WordPress после этого всё видно и редактируется руками, как в методичке.

## Запуск

```bash
cd lab7_wordpress
./setup.sh
```

- Сайт: http://localhost:8081/
- Консоль: http://localhost:8081/wp-admin/ — логин и пароль `WP_ADMIN_USER` / `WP_ADMIN_PASSWORD` в `lab7_wordpress/.env` (генерируются при первом запуске)
- phpMyAdmin: http://localhost:8082/ — `MYSQL_USER` / `MYSQL_PASSWORD` из того же `.env`

| Команда | Что делает |
|---|---|
| `./setup.sh` | запустить; при первом запуске — установить и наполнить сайт |
| `./setup.sh url http://IP:ПОРТ` | сменить адрес сайта (после смены порта или переезда), ссылки в контенте переписываются |
| `./setup.sh reset` | удалить сайт и БД и собрать заново |
| `./setup.sh down` | остановить (данные сохраняются) |

## Порты

Все в `lab7_wordpress/.env` (см. [.env.example](lab7_wordpress/.env.example)):

| Переменная | Что это | По умолчанию |
|---|---|---|
| `WP_PORT` / `WP_BIND` | сайт WordPress | 8081 / 0.0.0.0 |
| `PMA_PORT` / `PMA_BIND` | phpMyAdmin (по умолчанию только локально) | 8082 / 127.0.0.1 |
| `WP_URL` | полный адрес сайта, должен совпадать с `WP_PORT` | http://localhost:8081 |

MySQL наружу не публикуется (порт хоста не занимает), к нему ходят WordPress и phpMyAdmin по внутренней сети. Перед запуском `setup.sh` проверяет, свободны ли порты (`deploy/ports.sh`).

Переезд на другой порт проверен: `WP_PORT=8091` + `./setup.sh url http://localhost:8091` → сайт открылся на 8091, ссылки на картинки переписались (`Made 15 replacements`).

## Развёртывание на сервере

```bash
cp lab7_wordpress/.env.example lab7_wordpress/.env.server
# вписать: WP_PORT, PMA_PORT (выданные порты), WP_URL=http://IP_СЕРВЕРА:WP_PORT
./deploy/deploy.sh user@server --stack lab7_wordpress
```

Пароли можно оставить пустыми: их сгенерирует сервер, а при следующих деплоях они сохранятся. Посмотреть пароль администратора:

```bash
ssh user@server "grep WP_ADMIN_PASSWORD crm/lab7_wordpress/.env"
```

Проверено на тестовом сервере (`WP_PORT=18081`, `PMA_PORT=18082`): сайт собрался, все страницы отвечают 200, карта, шорткоды и форма на месте, ссылки на картинки ведут на адрес сервера. При повторном деплое пароли сохранились, и вход администратора проходит.

**Если компьютер за VPN/прокси.** Некоторые VPN подменяют DNS (адреса `198.18.x.x`), и WordPress отказывается скачивать с них темы, плагины и переводы («A valid URL was not provided»). На такой случай есть mu-plugin [wporg-hosts.php](lab7_wordpress/setup/wporg-hosts.php): он разрешает загрузку только с доменов `*.wordpress.org`.

## Ответы на контрольные вопросы (7-1)

1. **Что такое CMS, как они работают?** Система управления контентом — программа, которая позволяет размещать и менять информацию на сайте без программирования. Состоит из back-office (хранение и логика, админка) и front-office (то, что видит посетитель). Контент хранится в БД (здесь — MySQL), дизайн задаётся шаблонами (темами); при открытии страницы CMS подставляет контент из БД в шаблон.
2. **Что такое Denwer и для чего используется?** «Джентльменский набор веб-разработчика»: Apache, PHP, Perl, MySQL, phpMyAdmin в одной программе для запуска сайтов на домашнем компьютере, их тестирования и отладки. Сейчас его роль выполняют Open Server Panel, XAMPP или, как здесь, Docker-контейнеры.
3. **Как установить WordPress на локальный сервер Denwer?** Распаковать WordPress в каталог сайта (`domains\wptest.ru`), создать в phpMyAdmin БД `wptest` (`utf8_general_ci`), открыть сайт в браузере, создать `wp-config.php` (имя БД, пользователь `root`, пустой пароль, сервер `localhost`, префикс `wp_`), запустить установку, указать название сайта, логин, пароль и e-mail администратора. В Docker то же делают переменные `WORDPRESS_DB_*` и `wp core install`.
4. **Основные элементы Консоли WP.** Консоль (сводка), Записи (записи, рубрики, метки), Медиафайлы, Страницы, Комментарии, Внешний вид (темы, настройщик, виджеты, меню), Плагины, Пользователи, Инструменты, Настройки (общие, написание, чтение, обсуждение, медиафайлы, постоянные ссылки).
5. **Чем CMS отличаются от конструкторов сайтов?** CMS устанавливается на свой сервер. Есть полный доступ к коду и БД, можно ставить любые темы и плагины и переносить сайт, но обслуживание (обновления, хостинг, резервные копии) на вас. Конструктор (Tilda, Wix) — облачный сервис: сайт собирается из готовых блоков, а хостинг и обновления берёт на себя сервис. Зато возможности ограничены платформой, перенос сайта затруднён, и обычно нужна подписка.
